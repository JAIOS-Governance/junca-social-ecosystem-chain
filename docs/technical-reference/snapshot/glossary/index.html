Protocol Scope

Completed-state protocol architecture.

完成時のプロトコル・アーキテクチャ。

JUNCA Social Ecosystem Chain provides a trust, participation and value-circulation layer for institutional applications, digital assets and interoperable services. The architecture separates protocol governance, network operation, partner-owned asset administration and independent evidence.

JUNCA Social Ecosystem Chainは、制度的アプリケーション、デジタル資産、相互運用サービスを支える、 アクセス・アイデンティティ・価値循環の信頼基盤です。プロトコル統制、ネットワーク運用、 パートナー資産管理、独立証跡を明確に分離します。

Implemented / CI Verified

Certified Finality and Validator Epoch Safety

認証済みFinalityとValidator Epoch保護

JUNCA Social Ecosystem Chain verifies synchronized block ranges against certified finality evidence. The current source also validates trusted checkpoint anchors, canonical persisted state, authenticated peer frames and live runtime evidence bundles before acceptance. Each proof is bound to the chain identity, block height, round, block hash and active validator-set hash. Duplicate, unknown or invalid validator signatures are rejected, and strict greater-than-two-thirds voting power is required before a finality certificate is accepted.

JUNCA Social Ecosystem Chainは、同期対象のBlock Rangeを認証済みFinality証跡と照合します。現行Sourceは、Trusted Checkpoint Anchor、Canonical Persisted State、Authenticated Peer Frame、Live Runtime Evidence Bundleも受入前に検証します。各ProofはChain Identity、Block Height、Round、Block Hash、Active Validator Set Hashへ拘束されます。重複Validator、未知Validator、不正署名を拒否し、Finality Certificateの成立には厳格な3分の2超のVoting Powerを必要とします。

03

Fungible Asset Architecture

Supply, authority and treasury control.

供給・権限・トレジャリー統制。

Purpose & economics

Define function, operating domains, supply logic, distribution, vesting and off-chain obligations before selecting a contract standard.

用途、供給、配布、Vesting、会計・法務上の責任を先に確定します。

Authority & custody

Separate owner, mint, burn, pause, treasury and upgrade roles. Prefer multisig or institutional custody where the risk profile requires it.

Owner、Mint、Burn、Pause、Treasury、Upgradeの権限を分離します。

Compatibility gate

Each approved token standard, upgrade pattern and development toolchain passes client-level compatibility, negative testing and deployment verification before release.

承認対象のトークン規格、アップグレード方式、開発ツールは、公開前にクライアント互換性、Negative Test、配置検証を完了します。

Fixed supply

No post-release minting; migration planning becomes central.

Mintable

Requires controlled mint authority, limits and observable events.

Burnable

Requires clear holder/admin rights and supply reconciliation.

Upgradeable

Adds administrator and migration risk; must be explicitly governed.

04

Non-Fungible & Credential Architecture

Identity, provenance and metadata permanence.

識別性・来歴・メタデータ永続性。

Asset models

The asset layer supports single assets, collections and governed semi-fungible patterns for membership, certificates, access passes, authenticity records and licensed brand or IP assets.

Metadata discipline

Record schema, storage, integrity hash, update authority, retention, licensing and migration. Personal information should not be placed on-chain or in public metadata.

Distributed storageIntegrity and persistence planning; availability still requires operational stewardship.
Managed storageControlled service levels and access; introduces provider and continuity dependencies.
Hybrid recordOn-chain digest plus governed off-chain asset; requires recovery and migration evidence.

Interoperability Control Plane

Ethereum / ERC, BSC and TRON route architecture.

Ethereum／ERC・BSC・TRON相互運用経路。

Interoperability uses deterministic, fail-closed route validation, a bidirectional message-state engine and destination-chain execution contracts. Each route binds explicit network identity, custody, relayer quorum, finality, replay protection, limits and emergency controls.

相互運用は、決定論的なFail-Closed経路検証、双方向メッセージ状態機械、 対象チェーン実行コントラクトで構成します。各経路は、ネットワーク識別、Custody、 Relayer Quorum、Finality、Replay Protection、利用上限、緊急停止を明示的に結合します。

Route identity

Source and destination networks, contracts, assets and message domains are explicit.

Execution safety

Finality, quorum, replay protection, limits and paused-by-default release.

Acceptance

Custody binding, deployed-code verification, security review and live operational evidence.

Institutional multisig, separate guardian and KMS/HSM-backed relayer keys are release prerequisites.

Limits & incident control

Per-transaction and daily limits, emergency pause and an approved incident runbook.

Compatibility boundary / 互換性境界

BSC Testnet is identified by EVM Chain ID 97. TRON Shasta is identified astron-shasta; no fictitious EVM Chain ID is assigned. Solidity compilation does not prove TRON TVM compatibility. Target-chain compilation, deployment, source verification and independent security review are mandatory before route activation.

BSC TestnetはChain ID 97、TRON Shastaはnetwork identifier「tron-shasta」で識別します。 Solidityのコンパイル成功だけではTRON TVM互換性を証明しません。経路有効化前に対象チェーンでの検証を必須とします。

Asset administration

Institutional control of supply, minting, pausing, ownership and operational policy for a digital asset.

デジタル資産の供給、発行、停止、所有権、運用方針に対する制度的統制。

Protocol

Finality

The point at which a transaction is treated as sufficiently irreversible under a defined confirmation policy.

定義済み確認方針に基づき、取引を十分に不可逆と扱う時点。

Interoperability route

A governed message and asset pathway between explicitly identified networks.

明示されたネットワーク間のメッセージ・資産移動を統制する経路。

Governance

JAIOS Institutional Governance

The approved public designation for JUNCA protocol release, issuance and operational governance responsibility.

JUNCAのプロトコル公開、発行、運用統制責任を示す承認済み対外表記。

テスト資産が金銭的価値を表さないことを示す必須のテストネット表示。

統制された公開検証と証跡収集を目的とするMainnet以外の環境。

Controls that prevent a message, source transaction or nonce from being executed more than once.

メッセージ、送信元取引、Nonceの重複実行を防止する統制。

Governance

必要証跡と承認が揃うまで進行を停止するFail-Closed型の判断点。
